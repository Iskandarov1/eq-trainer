# EQ Trainer — project guide

Personal emotional-intelligence trainer based on Daniel Goleman's framework. Source-of-truth docs: `..\Daniel Goleman 1 month plan.pdf` and `..\Add a _Next Level_ section .docx`. Product spec: `PRD.md`.

## Stack
- React 18 + Vite 6 (`base: './'` — the build must keep working when `dist/index.html` is opened from disk via `file://`). Single JS bundle only — `file://` cannot load split chunks, so never introduce dynamic `import()` or manualChunks. The inline `fileProtocolClassicScript` plugin in vite.config.js rewrites the built index.html to a classic deferred script and strips `crossorigin` (module scripts are CORS-blocked on `file://`); that stays safe only while the bundle contains no import/export/import.meta. Side effect: the classic bundle's minified top-level declarations live in the GLOBAL scope — never add other inline/classic scripts to the built page (single-letter identifier clashes are a SyntaxError that kills the whole bundle).
- recharts for charts; `@supabase/supabase-js` (backend, via `src/api.js` only); `pdf-lib` + `@pdf-lib/fontkit` (client-side PDF reports). Plain CSS in `src/styles.css`. No TypeScript, no router — add no further dependencies.

## Commands
- `npm run dev` — dev server
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the build
- `node scripts/build-fonts.mjs` — regenerate the subsetted Noto Sans base64 modules in `src/fonts/` (needs the TTFs in `scripts/`)
- `node scripts/test-pdf.mjs` — smoke-test PDF generation in EN/RU/UZ (throws on any missing glyph)

## Architecture
- `src/App.jsx` — auth shell (`App`) + the trainer (`TrainerApp`, rendered with `key={uid}` so a user switch fully remounts state); route state object (`{page, emotion?}`), header/nav, breadcrumbs, toast, export/import, legacy-import modal, sign-out flow, sync badge.
- `src/api.js` — the ONLY module that touches Supabase (auth, Postgres, Storage). Local-first: per-user offline op queue (`eqTrainerQueue:<uid>`), debounced dirty markers, flush engine with error classes, pull+queue-aware merge. With `src/config.js` empty the app runs in v1 local mode under the legacy storage key.
- `src/pdf.js` — client-side PDF reports (pdf-lib + fontkit + `src/fonts/` base64 subsetted Noto Sans; fonts are inlined because `fetch()` of local assets fails on `file://`).
- `src/components/AuthScreen.jsx` — trilingual sign-in/sign-up (own local lang state, `eqAuthLang`).
- `src/components/Reports.jsx` — daily records list (entries + completed journey days), in-app report view, PDF download.
- `src/content.js` — ALL user-facing text and program content. Every string is `{en, ru, uz}`; render via `L(lang, s)` or the `t()` helper (UI table). Never hardcode display text in components. Uzbek uses Latin script with ʻ (U+02BB) for oʻ/gʻ and ʼ (U+02BC) for tutuq belgisi; because Uzbek is verb-final, sentence starters (`ph`) are nominal constructions ending in a dash/`qachonki`/`chunki` so the typed continuation stays grammatical.
- `src/store.js` — localStorage persistence (per-user `eqTrainerData:<uid>`, legacy `eqTrainerData` in local mode), analytics (mastery, intensity series, badges), `newId()` (always a real RFC-4122 v4 — server `entries.id` is uuid-typed), `normalizeData()`, `fmtDate()`.
- `src/components/` — Dashboard, Journey (30-day plan), NextLevel (module cards + Final Tips), EmotionModule (Learn/Practice/Journal/Progress tabs), BreathingGuide, ErrorBoundary.

## Data shape
```js
{ lang: 'en'|'ru'|'uz',
  journey: { startDate: 'YYYY-MM-DD'|null, days: { [n]: { fields: {}, saves?: { [practiceId]: ISO }, done: bool, doneAt?: ISO } }, ritual: { morning, day, evening } },
  entries: { anger: [], shame: [], fear: [] },
  checkins: { 'YYYY-MM-DD': { morning|day|evening: { text | fields: { intention|feel|why|how }, savedAt? } } } }
```
Daily check-ins (Journey.jsx, shown to everyone from day 1): one record per LOCAL calendar day (`todayKey()`), each slot has its own Save/Edit. Two slot shapes (owner decision 2026-08-19): during journey days 1–7 the check-in renders as the merged `MergedCheckin` card INSIDE Today's practices (today's screen only) — each slot combines the intention question with the Week-1 feel/why/how questions (`CHECKIN_SUB` in content.js) and stores `{ fields: { intention|feel|why|how } }`; everywhere else (pre-start, weeks 2–4, after day 30) the standalone `DailyCheckin` card renders below with plain `{ text }` slots. Both shapes flow into the same checkins records/PDFs — renderers use `checkinSlotParts(slot, s)`. Week 1's old `checkins` practice is `legacy: true` in content.js: hidden on the day screen, kept so old saved answers still render in Reports/day PDFs — `savedAt` present = saved & locked; absent = editable draft. Drafts persist locally on every keystroke and survive `normalizeData()` deliberately (a half-typed morning answer must survive reopening the page), but only saved slots sync/appear in Reports/archive as PDF. Journey day practices (owner decision 2026-08-19) mirror this per SAVE UNIT: normally the whole practice card is one unit (`days[n].saves[practiceId]`), but a practice with `saveGroups: true` in content.js (Week 1's `checkins`) splits at every labeled field into its own unit (`saves['<pid>.<firstFieldId>']` — morning/noon/evening each get their own Save/Edit). A stamped unit is locked (answered fields render read-only, Save disabled until some field has real content, Edit unlocks); unsaved fields still persist per keystroke as before, and Reports/day-PDFs are unchanged (they already show only answered fields). `journey.ritual` is legacy (UI removed; still normalized + synced in profiles for backward compat; its text is seeded into the first check-in's drafts once).
Text-field convention: every question is pre-filled with a sentence start (field `ph`, rendered via `starterFor()`) that the user finishes by typing; one sentence per field — never combine two thoughts in one starter (no "and…" inside a template). Untouched starters count as empty and are stripped on save — checked via `isBareStarter(txt, ph)` in ALL THREE languages, because the starter gets captured as stored text in whatever language was active when the user clicked in, and must not stick after a language switch (any field rendering `stored ?? prefill` needs this check). The starter is the FIXED template part of an answer (owner decision 2026-08-12): when a stored answer still begins with the field's starter in any language, every renderer (form fields, saved check-in view, in-app reports, PDFs) passes it through `localizeStarter(txt, ph, lang)` so the template part displays in the current language while the user's own continuation stays as typed; stored text never mutates. Renderers that only have the stored key use `FIELD_PHS[key]` for the template lookup.

## Conventions & invariants
- **Sync invariants (see PRD §3.5):** `api.js` is the only Supabase surface. Entries are append-only inserts with the client uuid as PK — duplicate error 23505 counts as success; never upsert entries. Journey-day ops send only their own columns (`fields`+`saves` vs `done`/`done_at`) so a stale fields push can never revert `done` (`saves` rides with `fields` — they change together on every practice Save/Edit). Check-in ops (`{t:'checkin', date, slot}`) upsert only their own slot column of the `checkins` row — slots can never overwrite each other; unsaved drafts are never pushed. Check-in PDF snapshots are keyed by the latest slot `savedAt` (`<uid>/<date>_checkin_<hhmmss>.pdf`), so each save archives a fresh complete snapshot into the append-only bucket and the day's last file is the full record. PDF bytes never enter localStorage — the queue stores references, bytes are regenerated at flush; storage upload 409 counts as success. Storage object keys are ASCII only (`<uid>/<YYYY-MM-DD>_<emotion|dayNN>_<hhmmss>.pdf`). A failed queue write must surface visibly (silent drop = permanent data loss).
- **Never gate the app on a live session** — gate on cached uid + cached data; a failed offline token refresh degrades to offline mode, not a login screen.
- **Option selections are stored as stable keys** (e.g. `dignity`, `physical`), rendered via `optionLabel(lang, v)`. `OPTION_LABELS` also maps legacy English display strings — old saved data must always keep rendering (backward compatibility is required; never migrate/rewrite stored entries).
- Journal field keys get display names from `FIELD_LABELS` in content.js — add an entry there for any new practice field.
- Book quotes: `BOOK_QUOTES` in content.js — EN text is verbatim from Goleman's *Emotional Intelligence* PDF (research source #6, PRD §6) and must never be reworded; RU/UZ are translations. Rotation via `nextBookQuote()` (shuffled deck, no repeat until all 20 shown); rendered by `BookQuote` in App.jsx on every page open. New quotes must be verbatim-verified against the book text first.
- No secure-context-only APIs (`crypto.randomUUID` etc.) without a fallback — the app runs on `file://`.
- All state changes go through `update(fn)` (structuredClone + save); never mutate `data` directly.
- CSS: `color-mix()` needs a plain fallback declaration on the previous line; keep the ≤480px and `prefers-reduced-motion` media queries intact.
- BreathingGuide is parameterized: `pattern` ('calm478' = 4-7-8, fear protocol; 'three' = 3 deep breaths in 4/out 6, Pause Power / 30-Second Rule) and `target` (auto-stop after N cycles). Fields of `t: 'breathing'` may carry `pattern`/`target`. Placements are deliberate (PDF-justified or calm-first): W2 Pause Power + Visualization, W4 Rehearsal, one per emotion module, standalone Breathe page. Do not scatter it into cognitive/writing practices.
- Design system v2 (owner-directed, see PRD §8a — sources: Mindvalley structure, Cosmos colors, Breathwrk session): single theme, cream `#FAF7F1` page, white borderless cards radius 14, black pill buttons, ONE interactive accent `#DCA6D6` (pink-lilac) + olive `#565A2B` for completion, earth-tone module colors, gold only for badges/streak. Heavy grotesk headlines (`.serif` class is legacy-named but renders 800-weight sans), `.caps` for metadata. NO emojis anywhere (typographic glyphs ✓ ★ ✧ are allowed). No colored buttons; max one lavender `.insight-tint` card per screen. Breathing player: constant dark field, concentric circles, per-second countdown — do not re-introduce per-phase background swaps. Min 44px touch targets; celebrations only at days 7/14/21/30.

## QA checklist (manual — no test framework)
`npm run build`, then verify: save a practice from `dist/index.html` opened from disk; import a backup with `entries:{}` (must not white-screen); RU and UZ mode journal shows localized labels/values; new profile shows no focus suggestion; two same-day entries get unique chart labels; daily check-in — type a morning answer, close/reopen the page (draft survives), Save locks it, Edit unlocks, saved day appears in Reports with a working PDF; journey day — Save on a practice card locks all its fields (read-only view, saved time shown), Edit unlocks, Save stays disabled while every field is empty/bare starter, lock state survives reopening.

With Supabase configured additionally: sign-up → practice → row appears under the right uid + PDF in Storage; second account sees nothing of the first; offline save → queue grows → reconnect → no duplicates; day marked done, then fields edited elsewhere → `done` never reverts; legacy import previews counts and renames (not deletes) the old key; sign-out with unsynced changes warns; `node scripts/test-pdf.mjs` passes (Cyrillic + ʻ/ʼ glyphs).
